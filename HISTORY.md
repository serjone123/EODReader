# HISTORY.md — история изменений проекта

Этот файл ведётся всеми разработчиками и ИИ-агентами, работающими над EODReader.

## Правила

Каждая существенная правка должна иметь запись. Особенно обязательно фиксировать изменения, которые:

- меняют логику обнаружения пиков или классификации;
- меняют математические расчёты, фильтрацию, корреляцию, статистику или пороги;
- меняют формат входных/выходных данных или совместимость;
- меняют структуру конвейера обработки;
- исправляют баг, который мог влиять на научный/экспериментальный результат.

Для небольших механических правок достаточно одной строки. Для изменений логики нужна содержательная запись: **что изменено → зачем → что изменилось в поведении/расчётах → как проверено**.

Не переписывать историю предыдущих агентов. Новые записи добавлять сверху, сразу после раздела `## Записи`.

### 2026-09-13 — Уточнение семантики peak records EODPK v3 — Codex

- В `EODPK_FORMAT.md` зафиксировано, что порядок `Position` является следствием последовательного прохода исходного WAV: штатно сформированные пики идут по возрастанию, поэтому полная проверка сортировки при каждом открытии файла не требуется.
- Зафиксировано, что окна waveform соседних пиков могут перекрываться.
- Перекрытия не считаются ошибкой, не устраняются при сохранении и не дедуплицируются при построении envelope cache: каждый пик хранит и агрегирует собственное окно независимо.
- Отмечено, что будущие расчёты по уникальным временным отсчётам должны отдельно определить политику обработки перекрытий, чтобы избежать двойного учёта.
- Автор: Codex.

### 2026-09-12 — Документирование EODPK v3 — Codex

- Добавлен `EODPK_FORMAT.md` как отдельная рабочая спецификация бинарного формата `.eodpk` версии 3.
- Зафиксированы логическая раскладка файла, header, fixed-size peak records, raw waveform вокруг пиков, многоуровневый envelope cache, правила прямого доступа и поиск диапазона без глобального массива `FPeakPositions`.
- Отдельно зафиксировано важное различие между raw waveform для точного просмотра и envelope cache для больших диапазонов: envelope не является заменой исходному сигналу для STD/FIR.
- В документе также перечислены инварианты, требования к RAM, проверки для больших файлов и идеи, которые пока не входят в v3.
- Описание сопоставлено с текущим `IO.PeakStore.pas` и `Core.Types.pas`; форматная реализация пока не изменялась.
- Обнаруженные при сопоставлении моменты для дальнейшей проверки оставлены в `TODO.md`, чтобы не менять бинарный формат без тестов и подтверждения поведения.
- Автор: Codex.

### 2026-09-12 — Фоновые workers для открытия WAV и построения Overview — Codex

- Открытие WAV выполняется через `Threads.WavOpen.pas` в отдельном worker: тяжёлая работа не блокирует UI, предусмотрены прогресс, отмена и передача готовой `TEodGuiSession` в главный поток.
- Расчёт Overview для WAV вынесен в `Threads.Overview.pas`; worker независимо читает четыре канала, считает общую и поканальные min/max-огибающие и передаёт готовые массивы в UI.
- Расчёт Overview для EODPK вынесен в `Threads.PeakOverview.pas`; worker использует существующий envelope cache `.eodpk`, не перечитывая исходный аудиосигнал.
- Исправлено применение результатов EODPK Overview: после завершения worker UI теперь передаёт рассчитанные массивы в `FOverview.SetData` и `FOverview.SetChannelData`, а не только меняет диапазон просмотра.
- Исправлены ошибки lifecycle при отмене/закрытии формы и timing обновления состояния кнопки `Open WAV`.
- Проверено пользователем на больших WAV и EODPK: интерфейс больше не зависает при построении Overview; после исправления результаты отображаются корректно. Пользователь отметил, что EODPK Overview также стал работать быстрее.
- Автор: Codex.
