# AGENTS.md — правила работы для ИИ-агентов

Кратко о проекте: Delphi 12 / FireMonkey / Win32, приложение для анализа записей
EOD рыб. Подробности архитектуры, форматы и сборка — в `README.md` (прочитай его
перед началом работы).

## Конвенция именования модулей

Каждый `.pas`-модуль называется по схеме `Подсистема.Назначение.pas`, где
`Подсистема` — один из слоёв архитектуры (см. README.md, «Структура проекта»):

- `Core.*` — общие типы и конфигурация, не зависящие от остальных слоёв.
- `IO.*` — чтение/запись WAV, `.eodpk`, файловый кэш сигнала.
- `Signal.*` — фильтрация и статистика по сырому сигналу.
- `Detection.*` — корреляция, шаблоны, классификация, детектор пиков.
- `GUI.*` — форма, модель сессии, графики, диалоги.
- `Threads.*` — фоновые worker'ы.
- `Electrode.*` — геометрия электродов, разметка, локализация рыбы
  (подсистема появилась в 2026-09; см. `HISTORY.md`).
- `Video.*` — экспорт видео обзорной полосы и её наложение (overlay) на
видео эксперимента через ffmpeg (подсистема появилась в 2026-09; см.
`HISTORY.md`).

Перед добавлением нового модуля агент обязан:

1. Определить, к какой из существующих подсистем относится функциональность,
   и использовать соответствующий префикс.
2. Не вводить новый префикс без явного согласования с пользователем. Если
   функциональность не укладывается ни в одну подсистему — спросить, а не
   придумывать имя самостоятельно. (Пример уже случившейся ошибки: модуль
   локализации рыбы был по недосмотру назван `Source.Localization.pas`
   вместо `Electrode.Localization.pas`; исправлено 2026-09-14.)
3. Если агент замечает модуль, чьё имя не соответствует схеме, — сообщить об
   этом пользователю отдельно, а не переименовывать самостоятельно без
   согласования: переименование ломает ссылки в `.dpr`/`.dproj` и историю.

Исключение: `uReadWavMain.pas`/`.fmx` — исторически сложившееся имя главной
формы, сознательно не переименовывается.

## Самооценка возможностей агента

Перед выполнением нетривиальной задачи агент обязан трезво оценить, хватает ли ему знаний, контекста и технических возможностей для надёжного результата.

- Не маскировать нехватку компетенции уверенным тоном, догадками или искусственным усложнением решения.
- Если задача заметно выходит за пределы возможностей агента, остановиться на безопасной точке и прямо сообщить пользователю, что её лучше поручить более продвинутой модели/агенту.
- Если есть несколько вариантов и уверенности недостаточно, не выбирать рискованный вариант только ради видимости прогресса: обозначить неопределённость и предложить более сильному агенту выполнить эту часть.
- Не придумывать несуществующие API, свойства, архитектурные ограничения или результаты проверки. Если факт нельзя подтвердить чтением кода/документации или доступной проверкой, так и написать.
- Самооценка не должна быть поводом отказываться от обычной работы: для понятных локальных изменений агент должен выполнять задачу самостоятельно.
- При передаче задачи другому агенту оставить краткое описание: что уже проверено, где именно возникло ограничение и какой результат ожидается.

## Сборка и проверка

- Сборка — из корня: `cmd /c _build.cmd` (msbuild + rsvars.bat, Debug/Win32).
  Успех = строка вида `NNNN lines, X.XX seconds, ... bytes code` и отсутствие `error`.
- **Запускать приложение и тестировать его руками НЕ нужно** — скомпилировалось,
  значит работа сделана; запуск и проверку делает пользователь. Не трать токены
  на запуск exe, скриншоты, клики по окну, UIA-деревья и т.п.
- Если линкер пишет `F2039 Could not create output file Bin\ReadEOD.exe` —
  у пользователя запущено приложение. НЕ убивай чужой процесс: сообщи пользователю,
  что exe занят, он сам его закроет.
- Известные безвредные предупреждения (не трогать, если не попросили):
  `H2164 PeakPositions`, `W1000 MessageDlg deprecated`, `H2077 BestDistance`.

## Обработчики событий: назначать кодом, а не через форму

Главная ловушка этого проекта. Компоненты из `.fmx` и их события (`OnClick`, `OnChange`…)
связываются через RTTI **published**-секции формы. Если метод-обработчик оказался в
`private`, компилятор молча даёт лишь hint
`H2219: Private symbol '<ИмяОбработчика>' declared but never used` — а форма
**падает при загрузке** (EReadError), причём отловить это компиляцией невозможно.

Правила:

1. **Не полагайся на события в `.fmx`.** Обработчик назначай кодом в `FormCreate`
   (или там, где создаётся компонент):

   ```pascal
   FMyButton.OnClick := MyButtonClick;
   FMyCombo.OnChange := MyComboChange;
   ```

   В `uReadWavMain.FormCreate` это уже устоявшийся паттерн
   (`edStartSample.OnChange := edStartSampleChange;` — с поясняющим комментарием).

2. **Новые нестандартные контролы создавай кодом** (как `FPlayTimer: TTimer`),
   а не правкой `.fmx` — меньше зависимостей от published/RTTI и от дизайнера.
   В `.fmx` добавляй только простые статические вещи (кнопку с `Align/Text`),
   и тогда её обработчик всё равно назначь в `FormCreate`.

3. После любой правки `.fmx` проверь лог компиляции: если у метода-обработчика появился
   `H2219` — событие не привязалось; чини назначением кодом (п. 1), а не переносом объявления в published.

## Правила правки файлов

- `uReadWavMain.fmx` — текст ASCII с **CRLF**; переводы строк сохраняй.
  Выравнивание FMX: контролы с `Align = Left` сортируются по `Position.X`,
  т.е. визуальный порядок задаётся координатой X.
- Комментарии и UI — на русском языке.
- Не трогай артефакты сборки/IDE (`Bin`, `DCU`, `Win32`, `__history`,
  `__recovery`, `*.identcache`, `*.dproj.local`, `ReadEOD.res`).
- Кодировка: исходники и `.md` с кириллицей — UTF-8 с BOM (перекодированы
  2026-09-19). Новые файлы создавать так же: Delphi читает файл без BOM как
  ANSI, и русские строковые литералы в exe будут испорчены. `.fmx` — ASCII
  с CRLF. Не перекодировать файлы обратно.
## Git

- Не коммитить и не пушить без явной просьбы пользователя.
- `git stash` пересобирает состояние — если использовал stash для экспериментов,
  не забудь `pop` и пересборку после него.

## Здравый смысл по токенам

Цель — минимальная правка, чистая компиляция, отчёт. Диагностику веди по логу компилятора и чтению кода; «эксперименты» с запуском exe, бинарным grep по exe/dcu (ресурсы форм там в UTF-16 — обычный grep всё равно ничего не найдёт) и кликами по GUI не нужны.
